Daily Use — The Core Loop
Step 1 — Morning
Log your weight
On the Dash tab, tap UPDATE on the weight card and enter today's weight. Use a consistent time — first thing in the morning, after the bathroom, before eating. This builds your weight trend over time.
💡 Naked morning weight is the gold standard — same conditions every day means the trend is meaningful.
Step 2 — Throughout the day
Log meals as you eat them
Tap Log Meal and describe what you ate in plain English. The AI identifies the food and calculates macros automatically.

Examples of what to type:
2 scrambled eggs with butter and smoked salmon
chicken thigh 180g with roasted broccoli
100g ASDA roasted salted mixed nuts
double cream shake — 150g cream
✓ You don't need to be precise with grams every time. The AI handles estimation. For foods you eat regularly, save them to your Library and tap once to log.
Step 3 — End of day
Close out your day
When you're done eating, type any of these in the Log Meal box:
that's me done
done for today
all done
wrapping up
The AI generates your daily nutrition summary and a master.csv row — a single line you can copy and save to your nutrition log file. This is how your history builds up over time.
⚠ Don't forget this step. The daily row is only generated when you close out. If you forget, you can go back and log missed meals the next day before closing out.
Step 4 — Optional
Set your day mode
On the Dash, tap the day mode buttons to tell the app what kind of day it is:

🟢 Standard — normal day, full carb ceiling applies
🟡 Occasion — relaxed day, slightly higher carb allowance
🔴 Holiday — holiday mode, no ceiling enforcement

The AI adjusts its feedback and the ketosis badge responds accordingly.
CSV Files — What They Are
master.csv — your nutrition history
A plain text file you build up over time. One row per day, pipe-delimited:
DD/MM/YY|Calories|Protein|Carbs|Notes
09/05/26|2840|173|40|stir fry chicken
10/05/26|3100|155|62|holiday meal
Where it comes from: the "Close out your day" step generates a row you copy and paste into this file.

How to import it: Import tab → Import Nutrition History → select your master.csv file.

Why it exists: it's your permanent offline backup of every day's nutrition. Even if you clear the app, your history is safe in this file.
💡 Keep master.csv in your Google Drive or backed up somewhere safe. It's the most important file in your setup.
combined.csv — your wearable data
The output of the data pipeline. One row per day, containing all your wearable metrics — steps, sleep stages, heart rate, HRV, SpO2, weight — merged from all connected devices.

Where it comes from: the pipeline runs in Termux, reads your device exports from the inbox folder, and writes combined.csv to the tables folder.

How to import it: Import tab → Load combined.csv → select the file at:
/storage/emulated/0/maxhealth/data/tables/combined.csv
What it unlocks: the Trends tab comes alive with sleep, activity, and HR charts connected to your nutrition data.
Connecting Wearable Devices
How it works
MaxedHealth doesn't sync with wearables directly — it reads the export files that wearable apps produce. The pipeline (running in Termux) processes these files and merges them into combined.csv.

Supported devices: Withings, RingConn, Amazfit/Zepp. Any device that exports CSV also works via Add New Device.
Quickest method
Use distribute.sh
Export from your wearable app. The file lands in your Download folder. Then open Termux and run:
cd /storage/emulated/0/maxhealth/app/maxhealth && bash distribute.sh
distribute.sh finds the export, moves it to the inbox, and offers to run the pipeline — all in one step. Then import the resulting combined.csv in the Import tab.
⚠ Amazfit/Zepp note: The Zepp app exports an encrypted zip. Use ZArchiver (free, Play Store) to extract it to the inbox folder first, then run the pipeline without a password.
Manual method
Run the pipeline directly
Copy your export file to the inbox folder, then in Termux:
cd /storage/emulated/0/maxhealth/app
python update_health.py --device withings
python update_health.py --device ringconn
python update_health.py --device amazfit

Reports & Trends
Trends tab
Populated once you import combined.csv. Shows weight trend, sleep quality, heart rate, HRV, SpO2, and steps — all plotted over time and connected to your nutrition data. Select different time windows with the filter buttons at the top.
Reports tab
Available after 3+ days of nutrition logging.

Summary cards — average calories, protein, carbs, adherence %, streak, and best day for the selected period.

Query builder — ask specific questions: "how many days was protein below 140g?" or "days over carb ceiling this month?"

AI Brief — tap Generate Brief for a plain-English narrative of your nutrition period. For GBM patients, includes metabolic adherence analysis.
GBM Protocol Mode
What it does
If you selected GBM / Therapeutic Ketosis during onboarding (or in Settings → Carb Ceilings), the app:

• Sets a 50g daily carb ceiling
• Shows the ketosis zone badge on the dashboard — green when within ceiling, yellow when approaching, red when exceeded
• Adjusts AI meal logging feedback to flag carb-heavy foods
• Generates a GBM-specific metabolic adherence analysis in Reports → AI Brief
• Links to the full protocol documentation
📖 Read the GBM Patient Protocol Guide →
Written by a GBM patient in active remission. Covers the full metabolic protocol, supplement stack, and the evidence behind each element.
Holiday / occasion days
Going over the ceiling occasionally doesn't break the protocol. Use 🔴 Holiday mode for planned higher days — the app logs it honestly without flagging it as a failure. One day doesn't undo weeks of adherence. What matters is the trend.
Protecting Your Data
⚠ Your data lives in Chrome — back it up
MaxedHealth stores everything in Chrome's localStorage on your device. This is fast, private, and requires no account — but it means if Chrome clears its storage, your data is gone. This can happen if you clear Chrome's browsing data, if Android reclaims storage space, or if you do a factory reset.
Protect yourself with three habits:

1. Export regularly — Settings → Export Backup Now (JSON). Do this at least weekly.
2. Keep master.csv — copy your daily row to a text file after every close-out. This is your plain-text nutrition history that works independent of the app.
3. Save exports somewhere safe — Google Drive, email to yourself, or your PC. Not just on the phone.
How to restore from a backup
From JSON backup: Settings → Import Data → select your .json backup file. Everything restores exactly as it was.

From master.csv: Import tab → Import Nutrition History → select your master.csv. This restores your nutrition history but not library or settings.

Pipeline backups (combined.csv): if you've run the pipeline, automatic backups are at:
/storage/emulated/0/maxhealth/data/backup/
Up to 7 rotating backups are kept automatically.
Frequently Asked Questions
I logged a meal but the macros look wrong. How do I fix it?
Tap the meal in today's log and edit the values directly. If it's a food you eat regularly, save the corrected version to your Library so the AI uses your values next time.
What's the difference between Log Meal and the Library?
Log Meal uses AI to identify macros from a description — good for anything. The Library stores foods you eat regularly with locked macro values — tap once to log instantly, no AI needed.
Will I lose my data if I clear the app in Chrome?
Clearing Chrome's site data will wipe your localStorage — yes. Protect yourself by regularly using Settings → Export All Data (JSON) or Export Nutrition CSV. Keep master.csv backed up.
Can I use this on multiple devices?
Not automatically — the app stores data locally on the device you use. You can export your data from one device and import it on another via Settings → Export All Data.
Why does the Trends tab show no data?
Trends needs wearable data from combined.csv. It won't populate from meal logging alone. Connect a wearable device or manually import a combined.csv from the Import tab.
Is my data sent anywhere?
Only meal descriptions (text or photo) are sent to the AI for macro identification — nothing else. All nutrition history, weight, and health data stays on your device. No accounts, no cloud storage.
What is the carb ceiling and how do I change it?
The carb ceiling is your daily carbohydrate limit. When you hit it, the app flags it and suggests protein/fat only for remaining meals. Change it in Settings → Carb Ceilings. Standard GBM protocol is 50g. Standard day / holiday ceilings can be set independently.
The AI got the macros wrong for a food. Can I override it?
Yes — edit the values after logging, then save the food to your Library with the correct values locked. Library values always take precedence over AI estimates.
Glossary
master.csv
Your nutrition history file. One row per day, pipe-delimited. Built by copying the daily row generated at end-of-day close-out. Import via Import tab → Import Nutrition History.
combined.csv
Pipeline output. One row per day, containing merged wearable data — steps, sleep, HR, HRV, SpO2, weight. Import via Import tab → Load combined.csv to populate Trends.
Inbox
The folder where you drop wearable export files for the pipeline to process. Located at /storage/emulated/0/maxhealth/data/inbox/
Pipeline
The Python scripts (update_health.py + extractors) that run in Termux, read device exports from the inbox, and produce combined.csv.
distribute.sh
A shell script that moves wearable exports from your Download folder to the inbox and optionally runs the pipeline — the quickest way to process a new export.
Carb ceiling
Your daily carbohydrate limit. The ketosis badge turns red when exceeded. Set in Settings → Carb Ceilings. GBM protocol default is 50g.
Ketosis badge
The indicator on the dashboard showing whether you're within your carb ceiling. Green = on track. Yellow = approaching. Red = exceeded.
Library
Your personal food library. Locked macro values that never change. Tap any food to log it instantly without AI. Edit and lock values yourself.
Day mode
Standard / Occasion / Holiday. Sets which carb ceiling applies for the day and adjusts AI feedback accordingly.
AI Brief
A plain-English summary of your nutrition data for a selected period. Generated in Reports → AI Brief. GBM patients get metabolic adherence analysis.
