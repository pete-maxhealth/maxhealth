01 — First time only

Initial
setup.

Takes about 10 minutes. You'll never need to do this again.

Samsung Galaxy users: go to Settings → Security and Privacy → Auto Blocker and turn it off before installing. Turn it back on after setup is complete.
1
Install
F-Droid, Termux and Termux:Boot
F-Droid is an open-source app store. Install it first, then install Termux and Termux:Boot from inside F-Droid.
Not the Play Store. The Play Store version of Termux is outdated and won't work correctly. Use F-Droid only.
Get F-Droid → Get Termux →
2
Run once in Termux
One-command setup
Open Termux and paste this command. It installs everything and creates the correct folder structure.
curl -sSL https://raw.githubusercontent.com/pete-maxhealth/maxhealth/main/setup.sh | bash
02 — Every export

Getting data
in.

After setup, this is the routine every time you have new wearable data.

1
Export from your device
Get the file — don't rename it
Withings: Health Mate app → Profile → Download my data. Arrives by email as a zip starting with export_

RingConn: RingConn app → Profile → Export data. CSV file.

Amazfit / Zepp: Zepp app → Profile → Settings → Export Health Data. The app shows a password — write it down immediately. The zip has a numeric filename like 7084918973_1778514144808.zip
Do not rename export files. The pipeline identifies your device by the original filename. Renaming causes silent detection failure.
2
Quickest method
Run distribute.sh
The export lands in your Download folder. Open Termux and run:
cd /storage/emulated/0/maxhealth/app/maxhealth && bash distribute.sh
distribute.sh finds the export, moves it to the inbox, and offers to run the pipeline — all in one step.
Amazfit/Zepp only: the Zepp zip is AES-256 encrypted. Use ZArchiver (free, Play Store) to extract it to the inbox folder first, then run distribute.sh or the pipeline without a password.
3
Or run manually
Pipeline commands
Copy your export to the inbox, then run from Termux:
cd /storage/emulated/0/maxhealth/app python update_health.py # all devices python update_health.py --device withings python update_health.py --device ringconn python update_health.py --device amazfit python update_health.py --dry-run # preview only
Auto-backup: the pipeline backs up your existing combined.csv before writing. If anything goes wrong, restore via Import tab → Restore Backup.
4
Final step
Import into MaxedHealth
Open MaxedHealth → Import tab → Load combined.csv. Navigate to:
/storage/emulated/0/maxhealth/data/tables/combined.csv
Your wearable data populates Trends immediately.
03 — Reference

Source precedence
& backup.

How the pipeline handles multiple devices and protects your data.

Source precedence

When multiple devices report the same metric for the same date, the highest-priority source wins. Secondary sources fill gaps.

MetricPriority order
WeightWithings → manual → RingConn → Amazfit
HRVRingConn → Withings → Garmin
SleepRingConn → Withings → Garmin → Amazfit
StepsGarmin → Withings → RingConn → Amazfit
SpO2RingConn → Withings
Heart RateRingConn → Amazfit → Withings → Garmin

Change order: MaxedHealth → Import tab → Source Precedence.

Automatic backups

Every pipeline run backs up combined.csv and nutrition.csv with a timestamp. Up to 7 backups kept.

/storage/emulated/0/maxhealth/data/backup/combined_20260511_143022.csv

Restore: Import tab → Restore Backup.

Pipeline log

Every run writes a structured log. Nothing fails silently.

2026-05-11 14:30:22 | amazfit | extract | ok | 2 days processed 2026-05-11 14:30:22 | withings | extract | warn | No files found in inbox/ 2026-05-11 14:30:22 | pipeline | write | ok | combined.csv written (847 rows)

Location: /storage/emulated/0/maxhealth/logs/pipeline.log · Also visible in Import tab → View Pipeline Log.

04 — Troubleshooting

Something
not working?

?
Pipeline reports no data found
Check the inbox folder has the export file. Check it hasn't been renamed. For Amazfit/Zepp — extract with ZArchiver first, then run the pipeline without a password flag.
?
Can't find the inbox folder
Open your Files app and navigate to:
Internal storage → maxhealth → data → inbox
?
Still stuck
Check the pipeline log at /storage/emulated/0/maxhealth/logs/pipeline.log — it records exactly what happened and why. Or open an issue on GitHub →
